# Практична робота №23. Створення формальної специфікації програми

**Розділ VII. Методи доведення та верифікації програмних систем**  
**Тема 16. Доведення правильності програм. Формальні специфікації**

## Мета роботи

Описати функціональність одного use-case через формальний контракт операції, передумови, післяумови, інваріанти стану та перевірні сценарії.

## Обраний use-case

Обрано use-case простої навчальної системи: **запис студента на курс**.

Формалізована операція:

```text
enroll_student(student_id, course_id)
```

Операція додає студента до списку учасників курсу, якщо студент зареєстрований, курс існує, студент ще не записаний на цей курс і на курсі є вільне місце.

## 1. Межі операції

### Вхідні дані

- `student_id` - ідентифікатор студента. Допустимі типи: рядок або ціле число.
- `course_id` - ідентифікатор курсу. Допустимі типи: рядок або ціле число.

### Вихід

- Якщо операція успішна, вона повертає `True`.
- Якщо порушено контракт операції, генерується відповідний виняток:
  - `NotRegisteredStudentError` - студент не зареєстрований;
  - `CourseNotFoundError` - курс не існує;
  - `AlreadyEnrolledError` - студент уже записаний на цей курс;
  - `CourseFullError` - курс не має вільних місць.

### Побічні ефекти

- У разі успіху змінюється стан системи: пара `(student_id, course_id)` додається до множини записів.
- Кількість вільних місць для відповідного курсу зменшується на 1.
- У разі помилки стан системи не змінюється.

## 2. Формальна модель стану

Позначення:

- `Students` - множина зареєстрованих студентів.
- `Courses` - множина існуючих курсів.
- `capacity(c)` - місткість курсу `c`.
- `Enrollments` - відношення записів студентів на курси.
- `(s, c) ∈ Enrollments` означає, що студент `s` записаний на курс `c`.
- `enrolled_count(c)` - кількість студентів, записаних на курс `c`.
- `available_seats(c) = capacity(c) - enrolled_count(c)`.

## 3. Контракт операції

```text
Operation: enroll_student(student_id, course_id)
```

Нехай:

```text
s = student_id
c = course_id
```

### Preconditions

Операція може бути виконана лише тоді, коли виконуються всі умови:

```text
s ∈ Students
c ∈ Courses
(s, c) ∉ Enrollments
available_seats(c) > 0
```

Тобто:

- студент `s` зареєстрований у системі;
- курс `c` існує;
- студент `s` ще не записаний на курс `c`;
- курс `c` має хоча б одне вільне місце.

### Postconditions

Якщо всі передумови виконані, після завершення операції має бути істинно:

```text
Enrollments' = Enrollments ∪ {(s, c)}
Students' = Students
Courses' = Courses
capacity'(c) = capacity(c)
available_seats'(c) = available_seats(c) - 1
```

Для всіх інших курсів `k`, де `k ≠ c`:

```text
available_seats'(k) = available_seats(k)
```

Також операція повертає:

```text
result = True
```

Якщо хоча б одна передумова порушена:

```text
State' = State
```

Тобто стан системи не змінюється, а операція завершується винятком.

## 4. Інваріанти стану

Інваріанти мають бути істинними до та після виконання будь-якої коректної операції.

1. Ідентифікатори студентів і курсів не можуть бути `None` або порожніми рядками.

```text
∀s ∈ Students: s ≠ None ∧ s ≠ ""
∀c ∈ Courses: c ≠ None ∧ c ≠ ""
```

2. Місткість кожного курсу є невід'ємним цілим числом.

```text
∀c ∈ Courses: capacity(c) ∈ N0
```

3. Кількість записаних студентів не може бути меншою за 0 або більшою за місткість курсу.

```text
∀c ∈ Courses: 0 ≤ enrolled_count(c) ≤ capacity(c)
```

4. Кожен запис посилається тільки на зареєстрованого студента та існуючий курс.

```text
∀(s, c) ∈ Enrollments: s ∈ Students ∧ c ∈ Courses
```

5. Запис студента на конкретний курс є унікальним.

```text
∀s ∈ Students, ∀c ∈ Courses: count((s, c), Enrollments) ≤ 1
```

6. Кількість вільних місць завжди узгоджена з місткістю та кількістю записів.

```text
∀c ∈ Courses: available_seats(c) = capacity(c) - enrolled_count(c)
```

## 5. Перевірні сценарії

### Позитивні сценарії

| № | Початковий стан | Дія | Очікуваний результат |
|---|---|---|---|
| P1 | `S1 ∈ Students`, `C1 ∈ Courses`, `available_seats(C1) = 2` | `enroll_student("S1", "C1")` | Повертає `True`, запис `(S1, C1)` створено, вільних місць стало 1 |
| P2 | `S2`, `S3` зареєстровані, `C2` має 2 місця | `enroll_student("S2", "C2")`, потім `enroll_student("S3", "C2")` | Обидва записи створено, `available_seats(C2) = 0`, місткість не перевищено |
| P3 | `S4` зареєстрований, `C1` і `C3` існують | `enroll_student("S4", "C1")`, потім `enroll_student("S4", "C3")` | Один студент може бути записаний на різні курси |

### Негативні сценарії

| № | Початковий стан | Дія | Очікуваний результат |
|---|---|---|---|
| N1 | `Sx ∉ Students`, `C1 ∈ Courses` | `enroll_student("Sx", "C1")` | `NotRegisteredStudentError`, стан не змінюється |
| N2 | `S1 ∈ Students`, `Cx ∉ Courses` | `enroll_student("S1", "Cx")` | `CourseNotFoundError`, стан не змінюється |
| N3 | `(S1, C1) ∈ Enrollments` | повторно `enroll_student("S1", "C1")` | `AlreadyEnrolledError`, дубль не створюється, стан не змінюється |
| N4 | `available_seats(C3) = 0` | `enroll_student("S2", "C3")` | `CourseFullError`, місткість курсу не перевищується, стан не змінюється |

## 6. Відповідність реалізації специфікації

Реалізація міститься у файлі `enroll.py`.

У класі `CourseSystem` реалізовано:

- множину студентів `students`;
- словник курсів `courses`, де ключ - `course_id`, значення - місткість;
- словник записів `enrollments`, де ключ - `course_id`, значення - множина `student_id`;
- метод `enroll_student(student_id, course_id)`;
- метод `check_invariants()` для перевірки інваріантів стану;
- метод `snapshot()` для перевірки, що негативні сценарії не змінюють стан.

Перевірні сценарії реалізовано у файлі `test_enroll.py`.

Команда запуску:

```bash
python -m unittest -v test_enroll.py
```
